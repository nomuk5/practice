**最重要インサイト（1行）**：
「意欲はある夫婦」がすれ違うのは、**相手の状態が見えず、言い出すコストが高く、きっかけがないから**。この3つをAIが肩代わりすればいい。

## 2. 市場・社会課題

### 2-1. 数字で見る課題

| 指標 | 数値 | 出典・注意 |
|---|---|---|
| 婚姻関係にあるカップルのセックスレス率（2020年） | **51.9%** | 日本家族計画協会「ジャパン・セックスサーベイ2020」。「年数回程度」または「1年以上なし」をレスと定義 |
| 同（2024年） | **64.2%**（報道ベース） | All About・ABEMA Timesの報道。**協会の公式報告書で要確認**（2020年の女性全体の値も64.2%なので、取り違えの可能性がある） |
| レスのきっかけ | 「妊娠・出産」が男女とも約25%で最多 | 夫婦のセックスレス実態調査（第4報、2023年、既婚者635人のうち完全レスの人） |
| 夫婦で話し合ったことがない | 約62%（50人中31人） | 既婚者向けアプリ利用者への調査。n=50と小規模 |
| 愛情とレスが並存 | 約6割がレス状態にある一方、夫婦仲が良好と感じる人が過半数 | 2025年12月の予備調査（報道ベース） |

→ **「仲は良いのにレス」という層がまとまって存在する**。議論で狙った「意欲はある層」と一致する。

### 2-2. 市場規模（フェルミ推定・仮置き）

> どれも検証前の仮置きの数字。Phase 0 のインタビューとLPの反応で更新する。

- **TAM**：未就学児がいる夫婦は、出生数（年およそ70万人）×6学年で**約400万世帯**。ここに妊活夫婦と50〜60代の夫婦を足すと、さらに広がる。
- **SAM**：そのうちレス、またはレス傾向にある夫婦が約60%で240万世帯。そのうち「2人とも意欲はある」を約40%とみて**約100万世帯**。
- **SOM（3年）**：SAMの0.5%が有料化すると**5,000組 × 年7,800円 ≒ 年3,900万円**。個人事業としては十分。売却を狙うなら有料3万組（年2.3億円）規模が目安になる。

### 2-3. 追い風

- 海外では、AIを使った夫婦向けウェルネスに資金が集まっている（Arya が2026年3月に2,100万ドルを調達。30万組以上、年商8桁ドルと報道）。
- 国内でも夫婦の対話を支援するアプリが増えている（Towaly が会員1.3万人を突破して自治体連携を開始、「ふたり会議」のすきだよがVCから調達）。
- LLMの性能向上と価格低下で、**先回りして声をかけるパーソナルなAI**が個人開発でも作れるコストになった。

## 5. 解決策：プロダクト設計

### 5-1. デザイン原則（議論から導出）

1. **女性が主語**：入力・公開範囲・停止のすべてを女性がコントロールする。
2. **責めない**：赤（NG）に理由を求めない。赤が続いても責めない。
3. **ロマンチックだが、エロくない**：焚き火、キャンドル、揺らぎ、オレンジ。幼稚にもしない（キューピッドは使わない）。
4. **見られても恥ずかしくない**：アイコン、通知、画面の第一印象を「暮らし・ウェルネス」のアプリに見せる。
5. **いきなり「して」と言わない**：「同じ方向を向く」ところから始めて、階段を上る。

### 5-2. コア機能

#### ① 今日の灯り（3段階シグナル）

信号機（赤・黄・青）をそのまま使うと直接的すぎる。そこで**炎の強さ**に置き換える。

| 状態 | 表示 | 意味（夫に見える情報） | 夫に見えない情報 |
|---|---|---|---|
| 🌑 消灯（赤） | 今日はおやすみ | 今日は無理しない日 | 理由（生理、痛み、気分、疲れなど） |
| 🕯 種火（黄） | ぬくもりの日 | ハグやマッサージくらいなら嬉しい | 体調の詳細 |
| 🔥 焚き火（青） | 焚き火日和 | 予定を合わせられたら嬉しい | 何日目か、排卵の予測など |

- **妻の入力**：1日1回の通知から**1タップ**（3つのアイコン）。任意で一言を添えると、AIが分類して学習する（例：「胸が張ってて痛い」→ 黄寄りの赤）。
- **AIの予測**：周期データ（ヘルスケア連携または手入力）と過去の入力から、**向こう2週間の灯りを予報**する。妻が承認したものだけを夫に見せる。
- **急な変更**：赤は1タップでいつでも変えられる（幼稚園の欠席ボタンのイメージ）。夫には「予定が変わりました」とだけ通知し、理由は伝えない。
- **避妊用途ではないことを明示する**（§9 法規を参照）。

#### ② 灯（ともり）：先回りするAIキャラクター

- 設定：小さな炎の精。2人の焚き火を守る役。議論で出た「天使のささやき」の性格（基本はやさしく、ときどき少し意地悪）を持たせる。人間でも動物でもない存在にする。
- **夫向けのささやき**（例）
  - 「木曜は焚き火日和の予報。保育園のお迎え、代われそう？」（3日前のカウントダウン）
  - 「チャンスの前髪、今日まで。今夜は早めに帰ってみる？」
  - 「今週はぬくもりの日が続くよ。肩もみ5分、どう？」
- **妻向けのささやき**（例）
  - 「今日の灯り、教えて。タップだけでいいよ」
  - 「最近おやすみが続いてるね。無理しなくていい。ハグだけの日を作ってみる？」
- **予定の提案**：2人のカレンダーと灯りの予報を重ねて、「土曜の10〜13時、実家に預けられそう？」のように段取りまで提案する。
- **トーンの学習**：通知を無視した、反応した、嫌がった、を学習してリマインドの頻度と口調を調整する（Duolingoの「寂しいです」の良いところだけ取り入れる）。

#### ③ 階段（スモールステップのゲーミフィケーション）

「薪をくべるほど焚き火が育つ」というメタファーで設計する。

| 段 | 行動の例 | 狙い |
|---|---|---|
| 1 | おやすみ前に10秒ハグ／「ありがとう」を1つ伝える | 体に触れるハードルを下げる |
| 2 | 5分マッサージを交代でする | お互いへの気づかいと、身体接触 |
| 3 | 外で手をつなぐ。2人で散歩・カフェ（子どもを預けて） | 「同じ方向を見る」時間 |
| 4 | 一緒に焚き火やキャンドルの動画を見る／夜に灯りを落としてゆっくり話す | 揺らぎ・吊り橋効果のような気持ちの動き |
| 5 | 2人だけの時間を予定に入れる（昼の時間帯も含める） | 本来の目的へ |

- 実行すると2人の「焚き火」が育つ（アニメーション）。しばらく何もしないと、炎が**少し**小さくなる（責めない程度の喪失感）。
- 毎週、灯が「今週のおすすめ」を1つ出す。議論で出た「今週はこういうのやってみませんか」のイメージ。
- **赤が続く人の復活ルート**：階段を1段目まで自動で下げる。妻だけで完結するセルフケアの提案も入れる。

#### ④ 見られても大丈夫なデザイン

- アプリのアイコンと名前は焚き火やキャンドルにして、ウェルネス・暮らし系に見せる。
- 通知の文面は比喩だけで書く（「今夜は焚き火日和です」）。ロック画面では内容を伏せるのが初期設定。
- アプリにはパスコードまたは生体認証をかける。2人の画面は「ふたりの暖炉」のように見せる。

#### ⑤ 妊活モード（第二ターゲット向け）

- 「排卵日」という言葉は使わず、「焚き火週間」というストーリーで伝える。
- 義務感を減らすために、**直前の数日前から雰囲気づくりの階段を出す**。

### 5-3. なぜ今、AIなのか

| これまでのアプリ | AIエージェント時代 |
|---|---|
| ユーザーが開かないと何も起きない | **AIから話しかける**（先回り、カウントダウン） |
| 一律のルールで周期を予測 | 一言の自由入力から**その人固有のパターン**を学習 |
| 固定の通知文 | 関係の状態に合わせて**口調と提案を変える** |
| 予定調整は人がやる | カレンダーを読んで**段取りまで提案** |

### 5-4. ユーザー体験の流れ（夫婦の1週間）

1. **月曜**：灯が妻に「今週の灯り予報、これで合ってる？」と聞く。妻が1タップで承認する。
2. **月曜**：夫に「木曜は焚き火日和。今週の薪：寝る前の10秒ハグ」と届く。
3. **火・水**：ハグを実行すると焚き火が少し育つ。妻の画面にも、それが分かる演出が出る。
4. **木曜朝**：妻が体調不良で🌑を1タップ。夫には「今日はおやすみ。代わりに早く帰って、ごはん係はどう？」と届く。
5. **土曜**：灯が「予報が🔥に戻ったよ。午前中、実家に預けられそう？」と提案する。

## 8. 開発ロードマップ（AIフル活用）

基本方針は**作る前に検証する、作るときはAIで一気に作る**。各フェーズの終わりにGo/No-Go判定を置く。

### Phase 0：課題検証（Week 0〜2）

| やること | AIの使い方 | アウトプット |
|---|---|---|
| 当事者インタビュー（夫婦10組、男女別々に実施） | 質問設計、文字起こし（今回の議論と同じ流れ）、ClaudeでJTBDとインサイトを抽出 | インタビュー分析シート |
| 公開統計の精査（ジャパン・セックスサーベイ2024の原典など） | Deep Researchで出典を確認 | 市場ファクトシート |
| LPとウェイトリストの作成 | Claude CodeでLPを1日で作成。コピーのA/B案を量産 | LP（2〜3案） |
| 小額の広告テスト（3〜5万円） | 広告クリエイティブをAIで生成 | CTR、登録率 |

**Go基準**：インタビューで「お互い意欲はあるのにタイミングが合わない」が10組中6組以上。LPの登録率が10%以上。**妻側が「シグナルだけの共有ならOK」と答える割合が過半数**。

### Phase 1：コンシェルジュMVP（Week 3〜6）

アプリはまだ作らない。**LINE公式アカウントとAI**で「灯」を再現する。

- 妻には毎日 LINE で「今日の灯りは？（🌑／🕯／🔥）」のボタンを送る。
- 夫には灯りと「ささやき」を送る（Claude API で生成。最初の1〜2週は人が目を通してから送る＝Wizard of Oz）。
- 週1回、階段のお題を出す。
- 対象は5〜10組で4週間。終了時に夫婦別々にインタビューする。

**Go基準**：妻の入力が週4日以上の組が60%以上。「階段」を実行した週が全体の50%以上。**「やめたくない」と答えたのが妻・夫の両方で過半数**。

### Phase 2：ネイティブMVP（Month 2〜3）

| 領域 | 選択 | 理由 |
|---|---|---|
| アプリ | **Expo（React Native）+ TypeScript** | iOS/Android を1つのコードで。Claude Code との相性が良い |
| バックエンド | **Supabase**（Postgres、Auth、行単位セキュリティ、Edge Functions） | 夫婦間の閲覧制御を行単位セキュリティで厳密に書ける |
| AI | **Claude API**（日々のささやきは Haiku、週次の予報と提案は Sonnet） | 能動的な文面生成、自由入力の分類、トーン調整 |
| 通知 | Expo Notifications + スケジューラー（cron） | 先回り通知 |
| 課金 | RevenueCat | サブスクとA/B価格テスト |
| 分析 | PostHog | ファネル分析、フィーチャーフラグ |
| ヘルスケア連携 | HealthKit／Health Connect（周期データ） | 入力の負担を減らす |

**データモデル（概略）**

```
couples (id, created_at)
users (id, couple_id, role: 'primary'|'partner', ...)   -- 'primary'＝主導権を持つ側（妻）
raw_logs (id, user_id, date, mood, note, cycle_day ...) -- 本人だけが読める（行単位セキュリティ）
signals (id, couple_id, date, level: 0|1|2, source: 'self'|'forecast', approved)
                                                        -- 2人とも読めるのは承認済みのみ
steps (id, couple_id, stage, title, done_at)
nudges (id, user_id, sent_at, text, reaction)           -- トーン学習用
```

- **生ログとシグナルをテーブルの段階で分ける**。夫側からは生ログに物理的にアクセスできない。
- MVPの範囲：ペアリング、灯りの入力と共有、赤ボタン、灯のささやき（プッシュ通知）、階段（段1〜3）、焚き火の育成演出。
- 対象は TestFlight と内部テストで30組。

**Claude Code の使い方**：画面ごとの仕様をMarkdownで書いて渡し、実装まで任せる。テストは Playwright で自動化する。プロンプトの評価もスクリプト化する。**個人1人で約6〜8週の工数**を見込む。

**Go基準**：カップル連携率60%以上、W4継続40%以上、妻のNPSが +20 以上。

### Phase 3：公開β・課金開始（Month 4〜6）

- App Store／Google Play で公開する（年齢区分は17+または18+を想定。表現は審査ガイドラインに合わせる）。
- 課金を開始し、価格テストをする（月額680円／980円／1,480円、年額の割引率）。
- 予報モデルを個人ごとにチューニングし、妊活モードとカレンダー連携を追加する。
- プライバシーポリシーと同意フローを整え、外部レビュー（弁護士）を受ける。

**Go基準**：有料転換率（トライアルから有料）が30%以上。有料のカップル単位でM2継続70%以上。

### Phase 4：グロースと事業化の判断（Month 7〜12）

- 送客（託児、デイユース、マッサージ）、自治体の実証、企業の福利厚生パイロット。
- 年齢層を広げる（50〜60代向けの「ゆっくり焚き火」モード）。
- **事業化の判断**：有料1,000組に届いたら法人化と資金調達、または売却の打診を検討する。届かなければ、個人プロダクトとして低コストで運用を続ける。

## 9. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| **法規（薬機法）**：「この日は大丈夫」が避妊の判断に使われる | 医療機器プログラムとみなされる、健康被害 | **避妊・妊娠可否の判断には使わない**と明示する。シグナルは「気分・体調・希望」の共有と定義し、妊娠確率は表示しない |
| **個人情報**：月経・性生活の情報は機微な情報 | 漏洩時のダメージが致命的 | 生データと共有データを分離し、最小限だけ収集する。明示的な同意、削除権、データのエクスポート。行単位セキュリティと暗号化。AIへの送信は必要最小限にし、学習には使われない設定にする |
| **関係悪化・強要の道具化** | 夫が「青なのに」と迫るなど | 夫の画面に「青は約束ではない」を常に表示する。妻はいつでも共有を停止できる。DV・強要の兆候が見えたら専門窓口へ案内する |
| **ストア審査**（性的コンテンツ） | リジェクト、公開停止 | 表現はウェルネスと関係性の範囲にとどめる。性的に露骨な表現はしない。年齢区分を適切に設定する |
| **片方しか使わない** | 価値が出ない | オンボーディングを「2人で一緒に」設計する。招待の文面を魅力的にし、連携率をKPIに置く |
| **継続しない** | 解約 | 灯の先回り、焚き火の育成、週替わりのお題。Phase 1 で「続くか」を最優先で検証する |
| **ブランド毀損**（アダルト提携） | 女性ユーザーが離れる | 提携は女性の評価（NPS）を条件にする。小さく試してから広げる |
| **競合の参入**（ルナルナ、Towaly など） | 機能を模倣される | 世界観、女性主導の思想、夫婦ごとの学習データで差をつける。速さで勝つ |
