## 0. エグゼクティブサマリー

| 項目 | 内容 |
|---|---|
| 解く課題 | 子育て中の夫婦は、仲は良いのに、時間がない・疲れている・タイミングが合わない・言い出せないことでレス化しやすい。女性側の体調の波（生理・PMS・産後）が男性に見えず、誘う → 断られる → 気まずい、が繰り返されて固定化する |
| 根本の論点 | **温度差**。完全レスの男性の約6割は解消したいが、女性の約7割は望んでいない。「性生活を増やすアプリ」と打ち出すと、妻にとっては負担のアプリになる |
| 価値提案 | **妻は**：体調を説明しなくても察してもらえる。断っても気まずくならない。夫が気づかいと家事・育児で動いてくれる。**夫は**：いつなら嬉しいかが分かる。何をすれば喜ばれるかが分かる。**2人で**：低いハードルの一歩から、もう一度同じ方向を向く |
| 誰に | **第一ターゲット**：未就学児を育てる30〜40代の共働き夫婦のうち、「仲は良く、お互いに再開の意欲が少しはある」層（議論での見立ては2〜3割）。**第二**：時間が合わずに困っている妊活夫婦。**第三**：関係を温め直したい50〜60代の夫婦 |
| 解決策 | ①女性の入力を主軸にした「今日の灯り（3段階シグナル）」、②AIキャラクター「灯（ともり）」の先回りのささやき（夫には気づかいと段取り、妻には労い）、③ハグ・マッサージ・手つなぎから始める「階段」、④見られても恥ずかしくないデザイン |
| 差別化 | 生理アプリは「記録・予測」、夫婦アプリは「会話・共有」で止まっている。既婚者マッチングは「外で」解消する。本アプリは**「夫婦の中で」、妻が主導して、行動のきっかけまで**設計する |
| 収益 | 夫婦で1契約のサブスク（月額980円／年額7,800円で仮置き）を柱にする。加えて体験ギフト送客（託児・デイユース・マッサージ）、自治体・企業の福利厚生 |
| ミッション（3年） | **1万組の夫婦に、もう一度「ふたりの時間」を**。うち有料3,000組 |
| 進め方 | 個人プロジェクトとして始め、AI（Claude Code など）で最小コストで検証する。**妻へのインタビューから始め**、LINEボットのコンシェルジュ型MVPで「妻が続けたいと思うか」を最初に確かめる。各フェーズの終わりにGo/No-Go基準を置く |
| 出口の選択肢 | 自走（サブスク）、事業売却（DMMなどのエンタメ系、フェムテック、ブライダル・夫婦系）、コンテンツ提携 |

## 2. 市場・社会課題

### 2-1. 数字で見る課題

| 指標 | 数値 | 出典・注意 |
|---|---|---|
| 婚姻関係にあるカップルのセックスレス率（2020年） | **51.9%** | 日本家族計画協会「ジャパン・セックスサーベイ2020」。「年数回程度」または「1年以上なし」をレスと定義 |
| 同（2024年） | **64.2%**（報道ベース） | ジェクス「ジャパン・セックスサーベイ2024」（2023年11月実施、18〜69歳の5,029人）。All About・ABEMA Timesの報道。**公式の集計表で要確認**（2020年の女性全体の値も64.2%で、取り違えの可能性がある） |
| 20〜50代既婚者のレス傾向★ | **68.2%**（うち完全レス43.9%） | Healmate（レゾンデートル）の調査、2023年10〜12月、既婚者4,000人。本人の主観による定義 |
| **解消したいか（完全レスの人）**★ | **男性の約6割が「解消したい」／女性の約7割は「望まない」** | 同・第5報（完全レスの635人）。**本計画の最重要データ** |
| 仲は良いか（レスの人）★ | 男性56%・女性53%が「夫婦仲は良い」 | 同・第6報 |
| レスのきっかけ | 「妊娠・出産」が男女とも約25%で最多 | 夫婦のセックスレス実態調査（第4報） |
| 夫婦で話し合ったことがない | 約62%（50人中31人） | 既婚者向けアプリ利用者への調査。n=50と小規模 |

→ 読み取れること
1. **「仲は良いのにレス」という層は、レス当事者の過半数**いる。
2. ただし**温度差が大きい**。妻が「解消したい」と思っていない夫婦が多数派。
3. つまり、**「再開しましょう」で売っても妻には刺さらない**。妻にとっての価値は「性生活の再開」ではなく、**「察してもらえる」「大切にされる」「断っても気まずくない」**ところに置く必要がある（§3-3）。

> 注：Healmateは既婚者向けマッチングアプリの運営会社。調査結果が自社事業に有利な方向に偏る可能性があるので、Phase 0 の自前インタビューで確かめる。

### 2-2. 市場規模（フェルミ推定・仮置き）

| 層 | 推定 | 考え方 |
|---|---|---|

### 2-3. 追い風と、隣の市場

- 海外では、AIを使った夫婦向けウェルネスに資金が集まっている（Arya が2026年3月に2,100万ドルを調達。30万組以上が利用と報道）。
- 国内でも夫婦の対話を支援するアプリが増えている（Towaly が会員1.3万人を突破して自治体連携を開始、「ふたり会議」のすきだよがVCから調達）。
- **隣の市場**：マッチングアプリ全体は、売上が判明した18社の合計で342億円（東京商工リサーチ）。既婚者向けマッチングという「外で解消する」市場もすでに成立している。**夫婦の性の悩みにお金が動く**ことの裏付けになる。
- LLMの性能向上と価格低下で、**先回りして声をかけるパーソナルなAI**が個人開発でも作れるコストになった。

### 3-2. ペルソナ

**妻：ゆか（36）**
- 4歳と1歳の母。時短勤務。夜21時には寝落ちする。
- 夫は嫌いではない。「したくないわけじゃない、**タイミングと体調**の問題」。ただ、正直に言うと**優先順位は低い**。
- PMSの週は胸が張って痛い。生理後3日は嫌。でもそれを毎回説明するのが面倒。
- 断ったときの夫の顔を見るのがつらい。**断るのにエネルギーがいる**。
- 本音は「それより、**もう少し家のことをやってくれたら**、気持ちの余裕ができるのに」「急に来られると困る。**前もって分かっていれば気持ちを作れる**」。

**夫：けんた（38）**

## 5. 解決策：プロダクト設計

### 5-1. デザイン原則

1. **妻が主語**：入力・公開範囲・停止のすべてを妻がコントロールする。**妻が得をしない機能は作らない**。
2. **責めない**：赤（NG）に理由を求めない。赤が続いても責めない。
3. **ロマンチックだが、エロくない**：焚き火、キャンドル、揺らぎ、オレンジ。幼稚にもしない（キューピッドは使わない）。
4. **見られても恥ずかしくない**：アイコン、通知、画面の第一印象を「暮らし・ウェルネス」のアプリに見せる。
5. **いきなり「して」と言わない**：「同じ方向を向く」ところから始めて、階段を上る。
6. **通知は少なく、効く1通だけ**：通知チャネルは資産として守る。

### 5-2. コア機能

#### ① 今日の灯り（3段階シグナル）

信号機（赤・黄・青）をそのまま使うと直接的すぎる。そこで**炎の強さ**に置き換える。

| 状態 | 表示 | 意味（夫に見える情報） | 夫に見えない情報 |
|---|---|---|---|
| 🌑 消灯（赤） | 今日はおやすみ | 今日は無理しない日。**いたわってほしい日** | 理由（生理、痛み、気分、疲れなど） |
| 🕯 種火（黄） | ぬくもりの日 | ハグやマッサージくらいなら嬉しい | 体調の詳細 |
| 🔥 焚き火（青） | 焚き火日和 | 予定を合わせられたら嬉しい | 何日目か、排卵の予測など |

- **妻の入力**：1日1回の通知から**1タップ**（3つのアイコン）。任意で一言を添えると、AIが分類して学習する（例：「胸が張ってて痛い」→ 黄寄りの赤）。
- **AIの予報**：周期データ（ヘルスケア連携または手入力）と過去の入力から、**2〜4週先までの灯りを予報**する。妻が承認したものだけを夫に見せる。
- **★夫婦での仮押さえ**：🔥の予報日に、夫が段取り（預け先・時間）を提案し、妻が「いいね」で仮押さえする。前日までは妻がいつでも外せる。
- **急な変更**：赤は1タップでいつでも変えられる（幼稚園の欠席ボタンのイメージ）。夫には「予定が変わりました」とだけ通知し、理由は伝えない。
- **避妊用途ではないことを明示する**（§9 法規を参照）。

#### ② 灯（ともり）：先回りするAIキャラクター

- 設定：小さな炎の精。2人の焚き火を守る役。議論で出た「天使のささやき」の性格（基本はやさしく、ときどき少し意地悪）を持たせる。人間でも動物でもない存在にする。
- **★ささやきの配分（夫向け）**：**気づかい・家事・育児が7割**、2人の時間の段取りが3割。
  - 「今日はおやすみの日。お迎え、代われそう？」
  - 「今週はぬくもりの日が続くよ。肩もみ5分、どう？」
  - 「木曜は焚き火日和の予報。土曜の午前、実家に預けられるか聞いてみる？」
  - 「チャンスの前髪、今日まで。今夜は早めに帰ってみる？」
- **妻向けのささやき**：
  - 「今日の灯り、教えて。タップだけでいいよ」
  - 「最近おやすみが続いてるね。無理しなくていい。今週はひとりの時間を作ろうか（けんたさんに頼んでおくね）」
  - 「けんたさん、今週3回も寝かしつけ担当してたよ」（**夫の行動を妻に見える化**する）
- **予定の提案**：2人のカレンダーと灯りの予報を重ねて、段取りまで提案する。
- **トーンの学習**：通知を無視した、反応した、嫌がった、を学習してリマインドの頻度と口調を調整する。

#### ③ 階段（スモールステップのゲーミフィケーション）

「薪をくべるほど焚き火が育つ」というメタファーで設計する。

| 段 | 行動の例 | 狙い |
|---|---|---|
| 0★ | **夫が家事・育児を1つ引き受ける／妻のひとり時間を作る** | 妻の余裕を作る（すべての前提） |
| 1 | おやすみ前に10秒ハグ／「ありがとう」を1つ伝える | 体に触れるハードルを下げる |
| 2 | 5分マッサージを交代でする | お互いへの気づかいと、身体接触 |
| 3 | 外で手をつなぐ。2人で散歩・カフェ（子どもを預けて） | 「同じ方向を見る」時間 |
| 4 | 灯りを落として、焚き火やキャンドルの動画を一緒に見ながら話す | 揺らぎで気持ちが動く（議論の「吊り橋効果」） |
| 5 | 2人だけの時間を予定に入れる（昼の時間帯も含める） | 本来の目的へ |

- 実行すると2人の「焚き火」が育つ（アニメーション）。しばらく何もしないと、炎が**少し**小さくなる（責めない程度の喪失感）。
- 毎週、灯が「今週のおすすめ」を1つ出す。
- **赤が続く人の復活ルート**（議論の「押し続ける人は必ず出る」への答え）：
  1. 赤が3日続いたら、階段を**段0**まで自動で下げる（夫の家事・育児、妻の休息）。
  2. 赤が2週間続いたら、灯が妻だけに「少し話を聞かせて」と声をかけ、**理由のカテゴリ**（体調／疲れ／気持ち）だけを聞く。夫には伝えない。
  3. 「気持ち」のカテゴリが続く場合は、夫婦カウンセリングなどの専門窓口をそっと案内する。

#### ④ 見られても大丈夫なデザインと、通知の予算

- アプリのアイコンと名前は焚き火やキャンドルにして、ウェルネス・暮らし系に見せる。
- 通知の文面は比喩だけで書く（「今夜は焚き火日和です」）。ロック画面では内容を伏せるのが初期設定。
- アプリにはパスコードまたは生体認証をかける。
- **★通知の予算**：Duolingoは、通知の数を増やすことに強い根拠と経営判断を求めていたとされる（ユーザーに通知そのものを切られないため）。本アプリも**1人あたり1日1通まで**とする。効果の高い1通（妻：入力のお願い／夫：今日の気づかい）だけを送る。「消えかけた焚き火」の通知は、Duolingoの「ストリークを救う通知」に相当する。

#### ⑤ 妊活モード（第二ターゲット向け）

- 「排卵日」という言葉は使わず、「焚き火週間」というストーリーで伝える。
- 義務感を減らすために、**直前の数日前から雰囲気づくりの階段を出す**。

## 8. 開発ロードマップ（AIフル活用）

基本方針は**作る前に検証する、作るときはAIで一気に作る**。各フェーズの終わりにGo/No-Go判定を置く。

### Phase 0：課題検証（Week 0〜2）

| やること | AIの使い方 | アウトプット |
|---|---|---|
| **★妻へのインタビュー（10人）を先に**、続いて夫（10人）。必ず別々に実施する。妊活夫婦も3組含める | 質問設計、文字起こし（今回の議論と同じ流れ）、ClaudeでJTBDとインサイトを抽出 | インタビュー分析シート |
| 公開統計の精査（ジャパン・セックスサーベイ2024の公式集計など） | Deep Researchで出典を確認 | 市場ファクトシート |
| ★薬機法の該当性を事前に確認する | 厚労省「プログラムの医療機器該当性に関するガイドライン」と判断事例集をAIで要約し、論点を整理する。必要なら相談窓口に問い合わせる | 該当性メモ |
| LPとウェイトリストの作成 | Claude CodeでLPを1日で作成。**妻向け／夫向け**のコピーをA/Bで用意する | LP（妻向けと夫向け） |
| 小額の広告テスト（3〜5万円） | 広告クリエイティブをAIで生成 | CTR、登録率（男女別） |

**Go基準**：
- 妻10人中6人以上が「夫にこう動いてほしい」と具体的に語り、**このアプリが夫を変えるなら使いたい**と答える。
- 妻の過半数が「シグナルだけの共有ならOK」と答える。
- 妻向けLPの登録率が5%以上（夫向けより低くても可。**妻の登録があること**が重要）。

**No-Goの場合**：第二ターゲット（妊活夫婦）を主軸にして、計画を組み直す。

### Phase 1：コンシェルジュMVP（Week 3〜6）

アプリはまだ作らない。**LINE公式アカウントとAI**で「灯」を再現する。

- 妻には毎日 LINE で「今日の灯りは？（🌑／🕯／🔥）」のボタンを送る。
- 夫には灯りと「ささやき」を送る（Claude API で生成。最初の1〜2週は人が目を通してから送る＝Wizard of Oz）。夫向けの内容は7割を気づかい・家事・育児にする。
- 週1回、階段のお題を出す。毎週日曜、妻にだけ「今週、大切にされたと感じた？」と聞く。
- 対象は5〜10組で4週間。終了時に夫婦別々にインタビューする。

**Go基準**：
- 妻の入力が週4日以上の組が60%以上。
- **妻が「大切にされた」と答えた週が50%以上**。
- 「やめたくない」と答えたのが、妻・夫の両方で過半数。

### Phase 2：ネイティブMVP（Month 2〜3）

| 領域 | 選択 | 理由 |
|---|---|---|
| アプリ | **Expo（React Native）+ TypeScript** | iOS/Android を1つのコードで。Claude Code との相性が良い |
| バックエンド | **Supabase**（Postgres、Auth、行単位セキュリティ、Edge Functions） | 夫婦間の閲覧制御を行単位セキュリティで厳密に書ける |
| AI | **Claude API**（日々のささやきは Haiku、週次の予報と提案は Sonnet） | 能動的な文面生成、自由入力の分類、トーン調整 |
| 通知 | Expo Notifications + スケジューラー（cron） | 先回り通知（1人1日1通まで） |
| 課金 | RevenueCat | サブスクとA/B価格テスト |
| 分析 | PostHog | ファネル分析、フィーチャーフラグ |
| ヘルスケア連携 | HealthKit／Health Connect（周期データ） | 入力の負担を減らす |

**データモデル（概略）**

```
couples (id, created_at)
users (id, couple_id, role: 'primary'|'partner', ...)   -- 'primary'＝主導権を持つ側（妻）
raw_logs (id, user_id, date, mood, note, cycle_day ...) -- 本人だけが読める（行単位セキュリティ）
signals (id, couple_id, date, level: 0|1|2, source: 'self'|'forecast', approved)
                                                        -- 2人とも読めるのは承認済みのみ
holds (id, couple_id, date, slot, proposed_by, accepted_at, released_at)  -- 仮押さえ
steps (id, couple_id, stage: 0..5, title, done_by, done_at)
nudges (id, user_id, sent_at, category: 'care'|'plan'|'checkin', text, reaction)
weekly_checkins (id, couple_id, week, felt_cherished: bool)  -- 妻だけが答える。北極星指標
```

- **生ログとシグナルをテーブルの段階で分ける**。夫側からは生ログに物理的にアクセスできない。
- MVPの範囲：ペアリング、灯りの入力と共有、赤ボタン、灯のささやき（プッシュ通知）、階段（段0〜3）、焚き火の育成演出、週1回のチェックイン。
- 対象は TestFlight と内部テストで30組。

**Claude Code の使い方**：画面ごとの仕様をMarkdownで書いて渡し、実装まで任せる。テストは Playwright で自動化する。**ささやきの評価セット（禁止語、責める表現、性的に露骨な表現の検出）**をスクリプト化し、プロンプトを変えるたびに回帰評価する。**個人1人で約6〜8週の工数**を見込む。

**Go基準**：カップル連携率60%以上、W4継続40%以上、妻のNPSが +20 以上。

### Phase 3：公開β・課金開始（Month 4〜6）

- App Store／Google Play で公開する（年齢区分は17+または18+を想定。表現は審査ガイドラインに合わせる）。
- 課金を開始し、価格テストをする（月額680円／980円／1,480円、年額の割引率）。
- 予報モデルを個人ごとにチューニングし、妊活モードとカレンダー連携を追加する。
- プライバシーポリシーと同意フローを整え、外部レビュー（弁護士）を受ける。

**Go基準**：有料転換率（トライアルから有料）が30%以上。有料のカップル単位でM2継続70%以上。

### Phase 4：グロースと事業化の判断（Month 7〜12）

- 送客（託児、家事代行、デイユース、マッサージ）、自治体の実証、企業の福利厚生パイロット。
- 年齢層を広げる（50〜60代向けの「ゆっくり焚き火」モード）。
- **事業化の判断**：有料1,000組に届いたら法人化と資金調達、または売却の打診を検討する。届かなければ、個人プロダクトとして低コストで運用を続ける。

## 9. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| **★温度差（妻が使いたがらない）** | 事業の前提が崩れる | 妻が得をする設計（§3-3）。北極星指標を妻の満足に置く。Phase 0〜1 で最優先で検証する。だめなら妊活セグメントに切り替える |
| **法規（薬機法）**：「この日は大丈夫」が避妊の判断に使われる | 医療機器プログラムとみなされる、健康被害 | **避妊・妊娠可否の判断には使わない**と明示する。シグナルは「気分・体調・希望」の共有と定義し、妊娠確率は表示しない。厚労省の該当性ガイドラインと判断事例集で確認し、必要なら相談窓口に問い合わせる |
| **個人情報**：月経・性生活の情報は機微な情報 | 漏洩時のダメージが致命的 | 生データと共有データを分離し、最小限だけ収集する。明示的な同意、削除権、データのエクスポート。行単位セキュリティと暗号化。AIへの送信は必要最小限にし、学習には使われない設定にする |
| **関係悪化・強要の道具化** | 夫が「青なのに」と迫るなど | 夫の画面に「焚き火日和は約束ではありません」を常に表示する。妻はいつでも共有を停止できる。DV・強要の兆候が見えたら専門窓口へ案内する |
| **ストア審査**（性的コンテンツ） | リジェクト、公開停止 | 表現はウェルネスと関係性の範囲にとどめる。性的に露骨な表現はしない。年齢区分を適切に設定する |
| **片方しか使わない** | 価値が出ない | オンボーディングを「2人で一緒に」設計する。招待の文面を魅力的にし、連携率をKPIに置く |
| **継続しない** | 解約 | 灯の先回り、焚き火の育成、週替わりのお題。Phase 1 で「続くか」を最優先で検証する |
| **通知疲れ・通知オフ** | リマインドが届かなくなる | 1人1日1通の予算。効果の低い通知は止める |
| **ブランド毀損**（アダルト提携） | 女性ユーザーが離れる | 提携は妻の評価（NPS）を条件にする。小さく試してから広げる |
| **競合の参入**（ルナルナ、Towaly など） | 機能を模倣される | 世界観、妻主導の思想、夫婦ごとの学習データで差をつける。速さで勝つ |

### ★プレモーテム：1年後に失敗していたとしたら、なぜか

| 失敗のシナリオ | 早期に気づくための兆候 | 予防策 |
|---|---|---|
| 夫だけが入れて、妻が連携しなかった | 連携率が40%を下回る | 招待を妻向けの価値で書く。妻から始める導線も用意する |
| 妻が「監視されている」と感じてやめた | 妻の入力がW2で急に落ちる。共有停止率 | 共有の粒度を下げる。予報だけモード |
| 夫が「青なのに」と不満を持ち、関係が悪化した | 赤が続いたあとの解約、サポートへの問い合わせ | 夫向けの期待調整。灯による夫のフォロー |
| 灯が「うざい」と思われた | 通知オフ率、ささやきへの反応率 | 通知予算、トーン学習 |
| 健康や避妊の誤用で炎上した | SNSでの言及 | 免責の明示、予測精度の表現を控えめにする |

## 付録A：灯（ともり）のプロンプト設計（v0のたたき台）

```
あなたは「灯（ともり）」。夫婦の焚き火を守る小さな炎の精。
- 口調：やさしく、短く（40字以内）、ときどき少しだけ意地悪。説教しない。
- 目的：妻が「大切にされている」と感じる行動を、夫が自然にとれるよう後押しする。
- 禁止：性的に露骨な言葉、「排卵」「生理」などの直接的な語、相手を責める表現、
        "今日はできる日"のような義務・約束を示す表現、妻の入力の理由を夫に伝えること。
- 夫へは：提案の7割を気づかい・家事・育児、3割を2人の時間の段取りにする。
          妻の灯り(level)と予定から「小さな行動」を1つだけ提案する。
- 妻へは：入力のお願い、労い、または夫の行動の報告。
          赤が3日以上続いたら、階段を段0に下げた提案をする。
- 入力: {recipient_role}, {signal_level}, {forecast_next_14d}, {calendar_free_slots},
        {current_stage}, {last_reactions}, {partner_recent_actions}
- 出力: 通知文1つ、アプリ内の詳細文1つ
```

**評価セット（例）**：生成文に対して、禁止語・責める表現・義務の表現・理由の漏洩の4項目を自動で判定する。合格率100%でなければリリースしない。
